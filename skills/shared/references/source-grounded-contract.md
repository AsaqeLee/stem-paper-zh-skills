# Source-grounded contract

在本仓库中，`source-grounded` 的目标是提升文本质量、可归因性与作者性，并通过更具体、更有依据的写法间接降低被判为 AI 文的风险。它**不**承诺任何检测结果，也**不**做针对检测器特征的优化。

## 何时使用

- 用户明确选择 `source-grounded`
- 用户没有指定模式，但已经给出足够多的 anchors，skill 可以建议切换
- 用户说“降 AIGC / 过检测”时，先把需求重述为 `natural` 或 `source-grounded` 的合法目标

任何情况下都**不要**静默升级到 `source-grounded`。

## 最小输入合同

必须同时具备：

1. `目标文本`：要改或要写的段落、节或 `.tex` 文件范围
2. `作者意图`：这段必须表达什么，哪些内容不能改
3. `至少 3 个 grounding anchors`：至少一条来自可核对来源、实验设置、项目约束、课堂概念或真实经历

如果作者意图不够明确，可以先给出候选意图让用户确认；不要直接自作主张。

## Fallback 规则

- 缺少作者意图或 anchors 时，先明确缺什么
- 写作任务：用户不补材料时，只给结构化提纲，或询问是否降级到 `natural`
- 润色任务：用户不补材料时，自动降级到 `natural`
- 绝不编造来源、数据、实验、个人经历或伪具体细节

## 写作与改写要求

- 每个关键改写都应能对应到用户给出的 anchor
- 用有依据的具体名词、约束、场景替换空泛指代和模板化收束
- 保持可读性、连贯性、术语一致性和 LaTeX 可替换性
- 不要为了“看起来不像 AI”而故意破坏行文节奏
- 除非任务显式允许，否则不要改变锁定事实、公式、引文、数值、label 或结论强弱

## 输出合同

`source-grounded` 的最终输出必须包含三段：

1. `revised text`
2. `anchor usage`
3. `gaps / assumptions`

正文本身不够，必须说明哪些 anchors 支撑了哪些关键表述，以及哪里仍然缺材料。

## 用户语言重述

“降 AIGC”“过检测”“查 AI”等说法属于用户语言，不是本仓库的产品术语。遇到这类请求时：

- 不承诺检测结果
- 不围绕检测器假设特征优化文本
- 重述为 `natural` 或 `source-grounded`
- 如果用户坚持“只要过检测，不管内容依据”，就停止

## 自检

- `可归因性`：关键改写是否都能映射到 anchors
- `具体性`：是否减少了空泛指代、万能过渡和模板总结
- `可读性`：是否保持了连贯性、术语一致性和 LaTeX 可替换性
- `保守性`：是否避免新增未给出的事实、实验结论、数据、引用或个人经历
